# CommitBook

Automated git commits for your markdown notebooks. Turn any git repository into a self-saving note-taking workspace with automatic version history.

## What It Does

CommitBook runs in the background and periodically commits all your changes using system scheduling (launchd on macOS, cron on Linux). Commit messages are generated by AI (Claude Code CLI, GitHub Copilot CLI, Codex CLI) or fall back to a descriptive timestamp format. You never lose your notes.

## Quick Start

```bash
# Install
cargo install --path crates/commitbook-cli

# Navigate to your notes repo
cd ~/my-notes

# Initialize CommitBook
commitbook setup

# Verify everything works
commitbook doctor

# Start auto-commits
commitbook start
```

That's it. Your notes will be automatically committed every hour.

## Commands

| Command | Description |
|---|---|
| `commitbook setup` | Initialize CommitBook in a git repository |
| `commitbook doctor` | Check system health and dependencies |
| `commitbook start` | Start automatic commits on schedule |
| `commitbook stop` | Stop automatic commits (preserves config and logs) |
| `commitbook status` | Show current state, schedule, and pending changes |
| `commitbook commit` | Manually trigger a commit cycle |
| `commitbook commit --dry-run` | Preview what would be committed |
| `commitbook set-schedule <expr>` | Change the commit schedule |
| `commitbook log` | View recent auto-commit log entries |
| `commitbook log --tail` | Follow the log in real-time |

### Schedule Presets

```bash
commitbook set-schedule hourly       # Every hour (default)
commitbook set-schedule every-30m    # Every 30 minutes
commitbook set-schedule every-4h     # Every 4 hours
commitbook set-schedule daily        # Daily at 9:00 AM
commitbook set-schedule "*/15 * * * *"  # Custom cron expression
```

## How It Works

```
commitbook start
       |
       v
  Install launchd plist (macOS) or crontab entry (Linux)
       |
       v
  Every hour (or configured interval):
       |
       v
  commitbook auto-commit --repo /path/to/notes
       |
       v
  1. Acquire file lock (prevent concurrent runs)
  2. Check git status for changes
  3. Verify changes have actual content diffs (not just mtime)
  4. If real changes found:
     a. Stage changes (respecting include/exclude patterns)
     b. Generate commit message (AI provider chain)
     c. Create commit
     d. Check for diverged remote, pull --rebase if safe
     e. Push to remote
  5. Log results (JSON-lines format)
  6. Release lock
```

## AI Commit Messages

CommitBook generates commit messages using a provider chain. Each provider is tried in order — if one fails, the next is used automatically.

| Priority | Provider | Invocation | Status |
|---|---|---|---|
| 1 | GitHub Copilot CLI | `gh copilot suggest` | Available |
| 2 | Claude Code CLI | `claude -p "<prompt>"` | Available |
| 3 | Codex CLI | `codex --quiet "<prompt>"` | Available |
| 4 | Timestamp fallback | Generated locally | Always available |

Example fallback message: `Writing 2026-04-07 14:30:02 (3 modified, 1 new)`

Run `commitbook doctor` to see which providers are available on your system.

## Configuration

### Global Config (`~/.CommitBook/config.toml`)

Stores the registry of all managed repositories and AI provider settings.

```toml
version = "1.0.0"

[repos]
"/Users/you/notes" = { enabled = true, schedule = "0 * * * *" }
"/Users/you/journal" = { enabled = true, schedule = "0 9 * * *" }

[ai]
providers = ["gh-copilot", "claude-cli", "codex-cli", "fallback"]
```

### Local Config (`<repo>/.CommitBook/config.toml`)

Per-repository settings.

```toml
enabled = true
schedule = "0 * * * *"
created_at = "2026-04-07T10:00:00Z"

[git]
auto_push = true
branch = "main"

[files]
include = ["*.md", "*.txt", "*.org"]
exclude = ["draft-*", "*.tmp"]

[logging]
level = "info"
max_log_files = 30
```

## Logs

Auto-commit logs are stored at `.CommitBook/logs/YYYY-MM-DD.log` in JSON-lines format:

```json
{"ts":"2026-04-07 14:00:01","level":"INFO","msg":"Auto-commit cycle started"}
{"ts":"2026-04-07 14:00:01","level":"INFO","msg":"Changes detected: 2 modified, 1 new","files":["notes.md","todo.md","ideas.md"]}
{"ts":"2026-04-07 14:00:02","level":"INFO","msg":"Commit created: a1b2c3d","provider":"claude-cli"}
{"ts":"2026-04-07 14:00:03","level":"INFO","msg":"Pushed to origin/main"}
```

Logs older than 30 days are automatically cleaned up.

## Architecture

CommitBook is built as a Cargo workspace with shared core logic:

```
crates/
  commitbook-core/    # Config, git, AI, scheduling, logging (zero UI)
  commitbook-cli/     # Command-line interface
  commitbook-tui/     # Terminal dashboard (ratatui)
  commitbook-web/     # Web dashboard (axum + htmx, embedded in binary)
```

All UI layers import `commitbook-core`. Each crate compiles independently and produces its own binary.

## Troubleshooting

### Auto-commits not running

```bash
# Check system health
commitbook doctor

# Check current state
commitbook status

# Check scheduler (macOS)
launchctl list | grep commitbook

# View logs
commitbook log
```

### Push failures

CommitBook detects diverged remotes and attempts `pull --rebase` when safe. If manual resolution is needed, auto-commits pause and the error is logged. Check logs and resolve manually:

```bash
commitbook log
git pull --rebase
commitbook start
```

### Reset CommitBook

```bash
commitbook stop
rm -rf .CommitBook/
commitbook setup
```
