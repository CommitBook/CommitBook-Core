# CommitBook

Automated git commits and sync for your markdown notebooks. Turn any git repository into a self-saving, self-syncing note-taking workspace.

## What It Does

CommitBook runs in the background and periodically:
1. **Commits** all your local changes (works offline)
2. **Syncs** with the remote using section-aware three-way merge (when online)

Commit messages are generated by AI (GitHub Copilot CLI, Claude Code CLI, Codex CLI) or fall back to a descriptive timestamp format. You never lose your notes.

## Quick Start

```bash
# Install
cargo install --path crates/commitbook-cli

# Navigate to your notes repo
cd ~/my-notes

# Run your first sync (auto-initializes .CommitBook/)
commitbook sync

# Start scheduled syncs
commitbook schedule hourly
commitbook start
```

That's it. CommitBook auto-initializes on first use — no setup command needed.

## Commands

| Command | Description |
|---|---|
| `commitbook sync` | Commit locally + pull/merge/push with remote |
| `commitbook start` | Start the sync scheduler (launchd/cron) |
| `commitbook stop` | Stop the sync scheduler |
| `commitbook status` | Show current sync state, schedule, and config |
| `commitbook schedule <expr>` | Change the sync schedule |
| `commitbook doctor` | Check system health and dependencies |
| `commitbook conflicts` | Show files with merge conflicts |
| `commitbook log` | View recent activity log |
| `commitbook login --token <T>` | Store a personal access token |
| `commitbook login --provider github` | Authenticate with a specific provider |

### Schedule Presets

```bash
commitbook schedule hourly         # Every hour (default)
commitbook schedule every-30m      # Every 30 minutes
commitbook schedule every-4h       # Every 4 hours
commitbook schedule daily          # Daily at 9:00 AM
commitbook schedule "*/15 * * * *" # Custom cron expression
```

## How It Works

```
commitbook sync
       |
       v
  1. COMMIT (always, even offline)
     - Stage changes (respecting include/exclude patterns)
     - Generate commit message (AI provider chain)
     - git commit
       |
       v
  2. SYNC (only if remote reachable)
     - Pull remote changes
     - Three-way section-aware merge (base vs local vs remote)
     - Push merged result
     - Update .CommitBook/base/ and state.toml
       |
       v
  3. On failure:
     - Local commit is preserved
     - Error logged to .CommitBook/logs/
     - Retry on next scheduled cycle
```

### Offline Mode

If the remote is unreachable, CommitBook still commits locally. With a 30-minute schedule and 6 hours offline, you get 12 local commits. When connectivity returns, the next sync merges and pushes everything.

### Section-Aware Merge

CommitBook parses markdown documents into sections (headings + content). During sync, it performs a three-way merge at the section level:

- **Case A**: Unchanged locally, changed remotely -> take remote
- **Case B**: Changed locally, unchanged remotely -> take local
- **Case C**: Both changed identically -> take either
- **Case D**: Both changed differently -> conflict (both versions preserved with markers)
- **Case E/F**: Added on one side only -> keep the addition
- **Case G**: Deleted vs edited -> conflict

## AI Commit Messages

CommitBook generates commit messages using a provider chain. Each provider is tried in order.

| Priority | Provider | Invocation | Status |
|---|---|---|---|
| 1 | GitHub Copilot CLI | `gh copilot suggest` | Available |
| 2 | Claude Code CLI | `claude -p "<prompt>"` | Available |
| 3 | Codex CLI | `codex --quiet "<prompt>"` | Available |
| 4 | Timestamp fallback | Generated locally | Always available |

Example fallback message: `CommitBook auto-commit: 2026-04-07 14:30:02 UTC`

Run `commitbook doctor` to see which providers are available on your system.

## Configuration

### `.CommitBook/` Directory

CommitBook stores all state inside `.CommitBook/` in the repository root. No global config or database.

```
.CommitBook/
  config.toml       # Settings (committed to git)
  auth.toml         # Credentials (gitignored)
  state.toml        # Sync state (gitignored)
  base/             # Base versions for merge (gitignored)
  logs/             # Activity logs (gitignored)
  .lock             # Prevents concurrent runs (gitignored)
```

Auto-initialization creates this directory and updates `.gitignore` on first use.

### `config.toml` (committed)

```toml
config_version = "1"
enabled = true
schedule = "0 * * * *"
created_at = "2026-04-07T10:00:00Z"

[git]
auto_push = true
branch = "main"

[files]
include = ["*.md", "*.txt"]
exclude = ["draft-*", "*.tmp"]

[logging]
level = "info"
max_log_days = 30
```

### `auth.toml` (gitignored)

```toml
[auth]
provider = "github"
token = "ghp_..."
```

## Logs

Activity logs are stored at `.CommitBook/logs/YYYY-MM-DD.log` in JSON-lines format:

```json
{"ts":"2026-04-07 14:00:01","level":"INFO","msg":"Auto-commit cycle started"}
{"ts":"2026-04-07 14:00:02","level":"INFO","msg":"Commit created: a1b2c3d","provider":"claude-cli"}
{"ts":"2026-04-07 14:00:03","level":"INFO","msg":"Pushed to origin/main"}
```

Logs older than 30 days are automatically cleaned up.

## Architecture

CommitBook is built as a Cargo workspace:

```
crates/
  commitbook-core/    # Config, git, AI, state, sync pipeline, merge engine
  commitbook-cli/     # Command-line interface
  commitbook-tui/     # Terminal dashboard (ratatui)
  commitbook-web/     # Web dashboard (axum + htmx)
```

All state is file-based (no database). The `.CommitBook/` directory is self-contained per repository.

### Key Modules (commitbook-core)

| Module | Purpose |
|---|---|
| `config/` | `LocalConfig` — reads/writes `.CommitBook/config.toml` |
| `state/` | `SyncState`, `AuthConfig`, base version management |
| `sync/` | Sync planner, pipeline (pull/merge/push), scheduler |
| `merge/` | Section-aware three-way merge engine |
| `transport/` | `RemoteTransport` trait: local repo, SSH, PAT, GitHub App |
| `ai/` | Commit message generation (Copilot, Claude, Codex, fallback) |
| `git/` | Git operations via `git2` and CLI |
| `cron/` | Scheduler (launchd on macOS, crontab on Linux) |
| `markdown/` | Parser, reassembler, frontmatter handling |

## Troubleshooting

### Syncs not running

```bash
# Check system health
commitbook doctor

# Check current state
commitbook status

# Check scheduler (macOS)
launchctl list | grep commitbook

# View logs
commitbook log
```

### Merge conflicts

CommitBook writes conflict markers inline (like git). Check for conflicts and resolve them:

```bash
commitbook conflicts
# Edit the conflicting files
commitbook sync
```

### Push failures

CommitBook commits locally even when the remote is unreachable. When connectivity returns, the next sync will push. Check logs for details:

```bash
commitbook log
```

### Reset CommitBook

```bash
commitbook stop
rm -rf .CommitBook/
# Next command will re-initialize
commitbook sync
```
