# CommitBook

Automated git commits for your markdown notebooks. Use any git repository as a Notion-like note-taking workspace with automatic version history.

## What It Does

CommitBook turns a git repository into a self-saving notebook. It periodically commits all your changes using system scheduling (launchd on macOS, cron on Linux), so you never lose your notes. Commit messages are generated by AI (GitHub Copilot CLI) or fall back to a descriptive timestamp format.

## Quick Start

```bash
# Install
cargo install --path .

# Navigate to your notes repo
cd ~/my-notes

# Initialize CommitBook
commitbook setup

# Verify everything works
commitbook doctor

# Start auto-commits
commitbook start
```

That's it. Your notes will be automatically committed every hour.

## Commands

### `commitbook setup`

Initialize CommitBook in the current git repository. Creates a `.CommitBook/` directory with configuration and log storage.

```bash
cd ~/my-notes
commitbook setup
```

Interactive prompts let you choose a schedule:
- Every hour (default)
- Every 30 minutes
- Every 4 hours
- Daily at 9:00 AM
- Custom cron expression

### `commitbook doctor`

Run health checks to verify all dependencies and configuration.

```bash
commitbook doctor
```

Checks include:
- Git installation and version
- Git remote connectivity
- GitHub CLI (`gh`) installation
- GitHub Copilot CLI availability
- Authentication status
- CommitBook configuration
- Scheduler (launchd/cron) accessibility
- Log directory write permissions

### `commitbook start`

Start automatic commits using the configured schedule.

```bash
commitbook start
```

### `commitbook stop`

Stop automatic commits. Preserves configuration and logs.

```bash
commitbook stop
```

### `commitbook set-schedule <expression>`

Change the commit schedule. Supports presets and raw cron expressions.

```bash
# Presets
commitbook set-schedule hourly
commitbook set-schedule daily
commitbook set-schedule every-4h
commitbook set-schedule every-30m

# Custom cron (every 15 minutes)
commitbook set-schedule "*/15 * * * *"

# Weekdays at 9am and 5pm
commitbook set-schedule "0 9,17 * * 1-5"
```

## Configuration

### Global Config (`~/.commitbook/config.toml`)

Stores the registry of all managed repositories and AI provider settings.

```toml
version = "1.0.0"

[repos]
"/Users/you/notes" = { enabled = true, schedule = "hourly" }
"/Users/you/journal" = { enabled = true, schedule = "daily" }

[ai]
providers = ["gh-copilot", "claude-cli", "codex-cli", "fallback"]
```

### Local Config (`<repo>/.CommitBook/config.toml`)

Per-repository settings.

```toml
enabled = true
schedule = "0 * * * *"
created_at = "2026-02-15T10:00:00Z"

[git]
auto_push = true
branch = "main"

[logging]
level = "info"
max_log_files = 30
```

## Commit Messages

CommitBook generates commit messages using a provider chain:

1. **GitHub Copilot CLI** (`gh copilot suggest`) -- AI-generated message based on diff
2. **Claude Code CLI** -- (future support)
3. **Codex CLI** -- (future support)
4. **Fallback** -- Timestamp format: `Writing 2026-02-15 14:30:02 (3 modified, 1 new)`

If a provider fails, CommitBook automatically tries the next one.

## Logs

Auto-commit logs are stored at `.CommitBook/logs/YYYY-MM-DD.log`:

```
[2026-02-15 14:00:01] [INFO] Auto-commit cycle started
[2026-02-15 14:00:01] [INFO] Changes detected: 2 modified file(s): notes.md, todo.md
[2026-02-15 14:00:02] [INFO] Commit message: Writing 2026-02-15 14:00:02 (2 modified)
[2026-02-15 14:00:02] [INFO] Commit created: a1b2c3d
[2026-02-15 14:00:03] [INFO] Pushed to origin/main
[2026-02-15 14:00:03] [INFO] Auto-commit cycle completed successfully
```

Logs older than 30 days are automatically cleaned up.

```bash

```

## How It Works

```
commitbook start
       |
       v
  Install launchd plist (macOS) or crontab entry (Linux)
       |
       v
  Every hour (or configured interval):
       |
       v
  commitbook auto-commit --repo /path/to/notes
       |
       v
  1. Acquire file lock (prevent concurrent runs)
  2. Check git status for changes
  3. If changes found:
     a. Stage all changes (git add -A)
     b. Generate commit message (AI or fallback)
     c. Create commit
     d. Push to remote
  4. Log results
  5. Release lock
```

- **Git** (any recent version)
- **Rust** 1.70+ (for building from source)

- **GitHub CLI** (`gh`) with Copilot extension (optional, for AI commit messages)

## Troubleshooting

### Auto-commits not running

```bash
# Check system health
commitbook doctor

# Check scheduler status (macOS)
launchctl list | grep commitbook

# Check logs
cat <repo>/.CommitBook/logs/$(date +%Y-%m-%d).log
```

### Push failures

CommitBook logs push failures but doesn't stop auto-commits. Changes are committed locally and will be pushed in the next cycle. Check your git credentials:

```bash
gh auth status
git push origin main  # Manual test
```

### Reset CommitBook

```bash
commitbook stop
rm -rf .CommitBook/
# Then re-setup
commitbook setup
```
